# Отчёт о выполнении практических работ № 9 и № 10

## Исходный проект

Продолжен существующий проект Transport Planner. Сохранены предметная область, URL-маршруты, шаблоны и консольная часть предыдущих практик. Пример Roomly из методических указаний адаптирован к сущностям транспортного сервиса.

## ПР9 — Django ORM

- Созданы модели `Route`, `Stop`, `Passenger`, `Trip` и связи между ними.
- Добавлены `ForeignKey`, `related_name`, ограничения удаления и миграции.
- Добавлена команда `import_legacy_data` для переноса исходной SQLite-базы ПР7 в `db.sqlite3` с сохранением первичных ключей.
- Старый `is_cancelled` преобразуется в `Trip.Status.ACTIVE` или `Trip.Status.CANCELLED`.
- Представления сайта переведены на ORM; SQL напрямую в Django views больше не используется.
- Реализованы поиск, фильтры, сортировка по белому списку полей, выборки по связям, `select_related`, `values`, агрегаты и аннотации.
- Для списка поездок реализованы пагинация и сохранение параметров фильтрации при переключении страниц.
- Доступность маршрутов учитывает только активные поездки.
- Добавлена обработка неверных параметров и отсутствующих объектов.

## ПР10 — Django Admin и развитие ORM

- Все доменные модели зарегистрированы в Django Admin.
- Настроены русские названия, списки, поиск, фильтры, сортировка, inline-связи и оптимизация `list_select_related`.
- Статусы поездок реализованы через `TextChoices`: активна, отменена, завершена.
- Добавлены `TripQuerySet` и `TripManager` с методами `active()`, `cancelled()`, `completed()`, `for_date()`.
- Добавлен уникальный slug маршрута, `get_absolute_url()` и отдельный URL по slug.
- Добавлен контекстный процессор с общими счётчиками для шаблонов.
- Добавлена условная интеграция Django Debug Toolbar для локального анализа SQL (включается после установки зависимости).

## Проверки и фактический статус аудита

Проверено при повторном аудите архива:

- `python -m compileall -q .` — успешно, синтаксических ошибок Python не обнаружено.
- Структура содержит четыре Django-приложения, модели и начальные миграции.
- Статический поиск подтвердил наличие `filter()`, `exclude()`, `values()`, `select_related()`, `annotate()`, `aggregate()`, `Count`, `Sum`, `Avg`, `Min`, `Max` и `Paginator` в ORM-представлениях.

**Ограничение проверки:** в среде аудита Django не установлен, а доступ к PyPI отсутствует. Поэтому `pytest` завершился на сборе тестов с `ModuleNotFoundError: No module named 'django'`; `manage.py check`, проверка миграций и интеграционные тесты в этой среде не выполнялись. Утверждать, что весь набор тестов пройден, нельзя. После установки зависимостей необходимо выполнить команды из раздела ниже на локальном компьютере.

Важная особенность переноса: исходная схема ПР7 хранит признак `is_cancelled`; импорт преобразует его в `ACTIVE`/`CANCELLED`. Статус `COMPLETED` не может быть восстановлен из старого булева поля и доступен для новых/редактируемых записей.

ПР10 в методических указаниях содержит контрольный пример Roomly (Room/Booking). В данном проекте сохранена предметная область Transport Planner и применены соответствующие аналоги (Route/Stop/Passenger/Trip); модели Room и Booking намеренно не добавлялись, чтобы не подменять индивидуальный проект.

## Первый запуск на новом компьютере

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_legacy_data
python manage.py createsuperuser
python manage.py runserver
```

Проверка:

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
pytest -v
```
